# Roadmap

## 설계 원칙

이 로드맵의 모든 단계는 **2단계 파이프라인** 구조를 따른다.

```
1단계 Market Regime → 2단계 Candidate Scoring
```

각 페이즈는 이 구조를 어디까지 완성하느냐로 구분된다.

---

## Phase 1 — 돌파매매 단대단 완성

목표: 돌파매매 하나로 1단계 + 2단계가 정상 작동하는 것을 먼저 만든다.

### 1단계: 돌파 시장 판정

핵심 산출물:

- 돌파 이벤트 자동 라벨링 (진입 후 +2% 도달 / -1% 이탈 기준)
- 최근 N일 돌파 성공률 자동 집계
- 시간대별 돌파 성공률 / 함정률
- 첫 돌파 vs 재돌파 우세도
- 시장 상태 분류기: `돌파 우호 / 중립 / 함정`

### 2단계: 돌파 종목 스코어링

핵심 산출물:

- 미모사식 1차 프레임 (테마/일봉/분봉/뉴스)
- 2차 실행 프레임 (Stage / Liquidity / Leadership / Market Fit / News-Timing)
- 1단계 regime을 입력으로 받아 컷오프 / 가중치 조정
- 종목 카드: `actionable / stalk / watch / too_extended / avoid`

### Phase 1에서 답해야 할 질문

- 최근 1주일 돌파매매 성공률은 어떤가
- 오늘 시장은 돌파 친화장인가, 함정장인가
- 어떤 돌파 패턴이 잘 먹히는가
- 어떤 시간대의 돌파가 유리한가
- 그 안에서 지금 들어갈 만한 종목은 무엇인가
- 함정장에서는 actionable이 거의 안 나오는가 (결합 검증)

### Phase 1 완료 기준

- 1단계와 2단계가 같은 파이프라인에서 자동으로 연결된다
- regime이 바뀌면 같은 종목의 라벨도 바뀐다
- 라이브 / 준라이브 데이터에서 일관되게 작동한다
- 다음 전략 추가 시 인터페이스를 그대로 재사용할 수 있다

---

## Phase 2 — 다전략 확장

목표: Phase 1에서 만든 2단계 구조를 다른 매매법으로 복제한다.

### 확장 전략

- 눌림목
- 상따
- 종베
- 스윙

### 각 전략마다 만드는 것

각 전략은 다음을 모두 갖는다.

1단계 (전략별 시장 판정):

- 전략별 진입/성공/실패 정의
- 전략별 자동 라벨링 규칙
- 최근 N일 성공률 자동 집계
- 전략별 시장 상태 분류기

2단계 (전략별 종목 선별):

- 전략별 입력 컨텍스트
- 전략별 스코어링 로직
- 1단계 regime을 받는 결합 인터페이스
- 종목 카드 라벨 (액션 정의는 전략마다 다를 수 있음)

### 핵심 산출물

- 전략별 1단계 + 2단계 모듈 (총 4세트)
- 공통 인터페이스 추상화 (1단계와 2단계의 입출력 규격 통일)
- 전략 간 비교 대시보드
- 시장 레짐 × 전략 적합도 매트릭스

### Phase 2에서 답해야 할 질문

- 오늘 시장에서 돌파보다 눌림이 더 좋은가
- 상따가 유효한 장인가, 함정장인가
- 종베가 먹히는 장인가
- 스윙으로 이어질 만한 주도 흐름이 있는가
- 같은 날 어떤 전략 조합이 가장 유효한가

### Phase 2 완료 기준

- 5개 전략(돌파 + 4개) 모두 1단계 + 2단계 구조로 작동한다
- 전략별 regime이 독립적으로 판정된다
- 한 화면에서 5개 전략의 시장 상태를 동시에 본다
- 새 전략 추가 비용이 기존 코드 복사 + 로직 교체 수준이다

---

## Phase 3 — 자동화와 학습

목표: 전략 로직이 안정된 후 운영 자동화와 지속 개선을 붙인다.

핵심 산출물:

- 전략별 백테스트 자동화 (가중치 / 임계값 자동 튜닝)
- 장 마감 후 일일 리포트 자동 생성
- 전략별 시장 상태 변화 추적 (요일/계절/이벤트별)
- 전략 추천 신뢰도 스코어
- 실시간 / 준실시간 모니터링 강화
- 시장 상태 자동 요약 (자연어 또는 시각 요약)

### Phase 3에서 답해야 할 질문

- 각 전략의 가중치가 시장 변화에 따라 어떻게 바뀌어야 하는가
- 어떤 시장 조건에서 어떤 전략이 가장 잘 먹히는지 누적 데이터로 보이는가
- 사용자에게 매일 자동으로 리포트를 줄 수 있는가

---

## 페이즈 간 의존성

- Phase 2는 Phase 1의 1단계/2단계 인터페이스가 완성된 후에 시작한다
- Phase 3는 Phase 2의 전략 모듈이 안정된 후 시작한다
- 인터페이스 추상화는 Phase 1 후반에 이미 의식하면서 짜야 한다 (Phase 2에서 다시 쓰기 안 하려면)
